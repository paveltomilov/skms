# Список изменений WebSocket интеграции

## Обзор

Интеграция WebSocket с бэкендом Django Channels, включая обработку сообщений инициализации симуляции, улучшенную диагностику ошибок и предотвращение множественных соединений.

---

## 1. Обработка сообщений инициализации симуляции

### Файлы:

-   `src/shared/types/websocket.ts`
-   `src/shared/lib/websocket/messageHandlers.ts`
-   `src/store/simulationSlice.ts`

### Изменения:

#### 1.1. Обновлен тип `SimulationInitMessage`

**Файл:** `src/shared/types/websocket.ts`

**Что сделано:**

-   Добавлена поддержка двух форматов сообщений `malfunctions`:
    1. Стандартный формат: `[{"malfunction_id": "c.0.1", "description": "..."}]`
    2. Формат с динамическими ключами: `[{"additionalProp1": "c.0.1"}]`

**Объяснение:**
Бэкенд может отправлять неисправности в разных форматах. Тип теперь поддерживает оба варианта через union type.

**Код:**

```typescript
export interface SimulationInitMessage {
	gate?: string;
	malfunctions: Array<
		| {
				malfunction_id: string;
				description?: string;
		  }
		| Record<string, string>
	>;
}
```

---

#### 1.2. Улучшена обработка сообщений инициализации

**Файл:** `src/shared/lib/websocket/messageHandlers.ts`

**Что сделано:**

-   Добавлен парсинг обоих форматов `malfunctions`
-   Извлечение ID неисправностей из объектов с динамическими ключами
-   Автоматическая установка активной задвижки при получении сообщения
-   Активация неисправностей в схеме

**Объяснение:**
При получении сообщения `{"gate": "g2", "malfunctions": [{"additionalProp1": "c.0.1"}]}`:

1. Извлекаются ID неисправностей (поддерживаются оба формата)
2. Устанавливается активная задвижка в Redux
3. Обновляются неисправности задвижки
4. Сохраняются данные симуляции в `simulationSlice`
5. Активируются неисправности в схеме через `circuitSlice`

**Ключевые действия:**

-   `setActiveGate(initMessage.gate)` - устанавливает активную задвижку
-   `setGateMalfunctions()` - обновляет неисправности задвижки
-   `setSimulation()` - сохраняет данные симуляции
-   `activateMalfunction()` - активирует неисправности в схеме

## 2. Улучшенная диагностика ошибок WebSocket

### Файлы:

-   `src/shared/lib/websocket/WebSocketManager.ts`

### Изменения:

#### 2.1. Улучшен обработчик ошибок `handleError()`

**Что сделано:**

-   Добавлен правильный маппинг состояний WebSocket (0=CONNECTING, 1=OPEN, 2=CLOSING, 3=CLOSED)
-   Добавлена информация о несоответствии состояний между `this.ws` и `error.target`
-   Добавлена детальная диагностика для состояний CONNECTING и CLOSED
-   Добавлена информация о длине токена

**Объяснение:**
Теперь при ошибке соединения в консоли отображается:

-   Текущее состояние WebSocket
-   Код состояния
-   Информация о токене (наличие и длина)
-   Возможные причины ошибки
-   Чеклист для диагностики

**Пример вывода:**

```javascript
{
  url: 'ws://127.0.0.1:8000/ws/simulation/student/?token=***',
  readyState: 'CONNECTING',
  readyStateCode: 0,
  errorType: 'error',
  hasToken: true,
  tokenLength: 228,
  stateMismatch: {
    description: 'Состояния WebSocket различаются',
    thisWsState: 'CONNECTING',
    errorTargetState: 'CLOSED',
    note: 'Это может указывать на то, что соединение закрылось во время установки'
  }
}
```

---

#### 2.2. Улучшен обработчик закрытия соединения `handleClose()`

**Что сделано:**

-   Добавлены описания кодов закрытия (1000, 1001, 1006, 1007, и т.д.)
-   Специальная обработка для кода 1006 (ненормальное закрытие)
-   Детальная диагностика с рекомендациями по исправлению

**Объяснение:**
Код 1006 означает, что соединение не может быть установлено. Теперь выводится:

-   Описание проблемы
-   Возможные причины
-   Рекомендации по исправлению

---

#### 2.3. Улучшено логирование переподключения

**Что сделано:**

-   Добавлено отслеживание кода последнего закрытия (`lastCloseCode`)
-   Отображение кода ошибки в логах переподключения
-   Специальное сообщение для ошибки 1006 при переподключении

**Объяснение:**
При переподключении теперь видно:

-   Номер попытки
-   Задержка до следующей попытки
-   Код последней ошибки
-   Специальные рекомендации для ошибки 1006

## 3. Предотвращение множественных соединений

### Файлы:

-   `src/shared/lib/websocket/WebSocketManager.ts`
-   `src/shared/hooks/useWebSocket.ts`

### Изменения:

#### 3.1. Улучшена логика в методе `connect()`

**Файл:** `src/shared/lib/websocket/WebSocketManager.ts`

**Что сделано:**

-   Добавлена проверка состояния `CONNECTING` (раньше проверялся только `OPEN`)
-   Предотвращение создания нового соединения, если уже есть активное или подключающееся
-   Логирование, когда соединение пропускается

**Объяснение:**
Раньше при повторных вызовах `connect()` создавались множественные соединения. Теперь:

-   Если соединение в состоянии `OPEN` или `CONNECTING` и параметры совпадают - соединение не создается
-   Выводится debug-лог о пропуске подключения

**Код:**

```typescript
if (
	this.ws &&
	(this.ws.readyState === WebSocket.OPEN ||
		this.ws.readyState === WebSocket.CONNECTING) &&
	this.url === url &&
	this.token === token
) {
	console.log(
		'[WebSocket] Соединение уже активно или подключается, пропускаем',
	);
	return;
}
```

---

#### 3.2. Улучшена логика в методе `doConnect()`

**Что сделано:**

-   Не закрывает активные или подключающиеся соединения
-   Закрывает только уже закрытые или закрывающиеся соединения
-   Добавлена защита от создания соединения при активном

**Объяснение:**
Раньше `doConnect()` всегда закрывал существующее соединение, что могло приводить к разрывам. Теперь:

-   Проверяется состояние существующего соединения
-   Активные соединения не закрываются
-   Если по ошибке вызывается при активном соединении - просто возвращается

---

#### 3.3. Убрана проверка `isConnected()` из `useWebSocket`

**Файл:** `src/shared/hooks/useWebSocket.ts`

**Что сделано:**

-   Удалена проверка `manager.isConnected()` перед вызовом `connect()`
-   Добавлен комментарий, объясняющий почему проверка не нужна

**Объяснение:**
`isConnected()` возвращает `true` только для состояния `OPEN`, но не для `CONNECTING`. Логика предотвращения дублирования уже есть в `connect()`, поэтому дополнительная проверка не нужна и может мешать.
